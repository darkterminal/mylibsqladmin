mylibsqladmin / dashboard

The tools the day-to-day work needs

Databases, queries, tokens, and permissions live in one place, with the same boundaries the server enforces.

SQL Studio

Run queries against a namespace and read the results in the browser, without exposing a CLI token to everyone on the team.

Access is checked twice

Navigation follows permissions, and every action is checked again on the server. Hiding a button is never the only guard.

  • policies · per-model authorization
  • teams · scoped membership
  • grants · per-database sharing

Tokens shown once

Tokens appear at creation and are stored as hashes. Revoke a single credential without rotating anything else.

  • one-time · plaintext reveal
  • SHA-256 · at rest
  • revoke · per token

Databases and groups together

Create a namespace, group related databases, then archive or restore them from the UI. sqld writes happen immediately.

Four roles, documented end to end

Each role has its own walkthrough with screenshots, mapped to the permissions it actually holds.

01

Super Admin

Full access across users, teams, databases, and tokens.

 02

Team Manager

Manages team membership, groups, and group tokens.

 03

Database Maintainer

Works on granted databases and mints their tokens.

 04

Member

Queries shared databases and inspects group membership.

From install to first query

One installer, one database, one token.

01 / INSTALL

Start the stack

The installer writes compose.yml for the web UI, sqld, and the optional proxy, then brings them up.

02 / CREATE

Add a database

Make a group, add a database, and confirm the namespace exists on disk under libsql-data/.

03 / SHARE

Hand out access

Mint a scoped token, copy it once, then connect a client or a teammate to that namespace.

Install in one command

Docker, Docker Compose, and openssl on the host are the only requirements. Everything else runs in containers.

shell 
$ curl --proto '=https' --tlsv1.2 -LsSf https://raw.githubusercontent.com/darkterminal/mylibsqladmin/refs/heads/main/scripts/installer.sh | sh

Before you run it

  • Docker Engine and Docker Compose v2
  • openssl for generating the application key
  • Port 8000 available on the host

On first boot

  • Migrations run automatically when the container starts.
  • With LIBSQL_SEED_DEFAULTS=true, one-time credentials are written to bootstrap-credentials.txt. Read them once, then delete the file.
